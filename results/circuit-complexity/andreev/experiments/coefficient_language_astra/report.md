# Coefficient-rule languages for uniform exact Andreev circuits

## 1. Recommendation and status

Use a **portfolio with two primary languages**:

1. An **index-program/affine-parameter language**, which generates every raw coefficient from public indices and a small shared parameter vector. Its central restriction is linearity in the learned numerical parameters, not equal magnitudes, coherence, symmetry, or linear dependence on indices. It can generate mixed signs, positional weights, sparse or dense table rows, and irregular branching. With a fixed structural skeleton its CEGIS learner is QF_LRA with Boolean conditionals.
2. An **additive contract language**, whose atoms have proved raw-LTF expansions and exact gate costs. Start with arbitrary raw ridge atoms, row-dependent table-code slices, and mixed localized windows; include permutation-rank atoms for regression. Search for a joint sign margin, not necessarily an exact sum or separate reconstruction of each character. This language makes the missing all-size lemma explicit but does not supply it.

Keep small index decision programs, finite-state transducers, and tensor/recurrence rules as alternative structure generators. They are not merely successive polynomial degrees. The cheapest useful implementation shares a common raw-circuit representation, arbitrary-table checker, exact rational evaluator, cost auditor, and counterexample archive across these languages. Do not force all of them into one nonlinear SMT problem.

**No new exact balanced asymptotic upper bound is established here.** The leading general research bound remains $5n^2/16$. A compact DSL, a compiler identity, and a successful finite multi-size fit are each insufficient to improve it. This report provides a design and small working compiler/tests, not a new circuit family or a solver campaign.

The parent's mask proposal is useful as one public-index feature. It should not be the definition of the language. A mask-only extension of independent full Walsh ladders remains quadratic; small periodic rank channels and the specified scalar Walsh shrinkers are already blocked. The promising relaxation is **row-dependent joint table/address coefficients**, with no requirement to assign each gate to one character or one table bit.

## 2. Model, quantifiers, and what uniformity must mean here

Use zero-based indices, $N=2^k$, $b_i=\bigoplus_{t<m}a_{i,t}$, $n=N+km$. A program $P$ with one fixed finite parameter tuple $\theta$ generates

$$g_j=\left[\sum_{c<N}\alpha_P(j,c;k,m,\theta)x_c+
\sum_{i<k,t<m}w_P(j,i,t;k,m,\theta)a_{i,t}\ge\tau_P(j;k,m,\theta)\right],$$

$$F=\beta_P(k,m,\theta)+\sum_{j\in J_P(k,m)}v_P(j;k,m,\theta)g_j
+\sum_cd_P(c;k,m,\theta)x_c+\sum_{i,t}e_P(i,t;k,m,\theta)a_{i,t}.$$

Output is $[F\ge0]$, and the size is $S+1$, $S=|J_P(k,m)|$. Neither coefficients nor the gate domain may depend on $x,a$. Index XOR, index permutations, and powers are computations performed by the generator, not additional circuit inputs. Proof notation such as a Walsh form is expanded into raw coefficients before a gate is counted.

The all-size objective is

$$\exists\text{ finite }P,\theta\quad\forall k\ge k_0\quad
\forall x,a:\quad [F_{P,\theta;k,m(k)}(x,a)\ge0]=x_{b(a)},$$

with $m(k)=\lfloor2^k/k\rfloor$, plus a proved gate bound and finite coefficient-generation algorithm. This balance gives $km=N-O(k)$ and $n\sim2N$. Exact balance is also possible along powers-of-two $k$, since $k\mid2^k$ there. A result only on that subsequence must say so; padding to other sizes needs a separate argument.

Training on sizes $\mathcal D$ asks only

$$\exists P,\theta\quad\bigwedge_{(k,m)\in\mathcal D}\ \forall x,a:\ C_{P,\theta;k,m}(x,a)=x_b.$$

This shares syntax and numerical parameters, **not independent fitted vectors $\theta_{k,m}$**. It still says nothing about untested sizes. Size-dependent values must be generated by the same declared expression/recurrence. A bounded list of exceptions is legal if charged explicitly, but does not count as discovering the general rule. Do not silently add an exception per new counterexample size.

There is a subtle uniformity issue: with no time restriction, a universal program can enumerate rational circuits at each size until it finds a correct one. If an all-size computable gate bound already guarantees success, that is a uniformization argument. Without that existence theorem it is not a construction, and it defeats the purpose of coefficient-rule discovery. The proposed object languages exclude invoking a solver/truth-table search during coefficient generation. They aim for explicit, output-sensitive generation; this is an additional research restriction, not part of the unrestricted LTF model.

Arbitrary reals remain permitted by the mathematical question. The proposed deliverables use explicit rationals/integers. At any single finite size, a threshold gate has a rational representation, but replacing each gate separately need not preserve a shared parametric rule. Nor does rational satisfiability of every finite training set imply one rational parameter vector satisfying every size. Do not invoke finite-domain rationalization to assert completeness of this language for all real uniform families.

## 3. Language A: public index programs with affine numerical holes

### 3.1 Two-level syntax

Use distinct types `Index`, `Pred`, and `Coefficient`. Public environments contain $k,m,N$, a gate-type tag, gate indices, and the current input-coordinate indices. They never contain raw input values.

A concrete skeleton specifies nested bounded gate loops, for example

```text
for type h in 0 .. T-1:
  for label u in 0 .. N-1:
    for level r in 0 .. m-1:
      emit gate(h,u,r)
```

Here $S=TNm$ exactly. Bounds may depend on earlier public loop indices; their summed cardinality is part of the program specification. A sparse condition can omit indices, but the safe unmerged bound still charges every potential emitted gate until omission is proved. A solver may choose among a finite menu of gate domains externally. Do not let unconstrained learned arithmetic change loop sizes inside a nominally fixed-size learner.

Public index expressions have the grammar

```text
I ::= integer | k | m | N | h | u | r | c | i | t
    | I+I | I-I | I*I | floor(I/d) | I mod d
    | bit(I,I) | popcount(I) | xor(I,I) | and(I,I)
    | base^I | if P then I else I | bounded_sum(index, bound, I)
P ::= I=I | I<I | bit(I,I)=1 | parity(I)=1
    | not P | P and P | P xor P
```

The divisor/base is fixed in a skeleton or obtained from a declared finite menu, with positive divisor and nonnegative exponent. General public arithmetic is not a solver operation after indices and structure are fixed. Every bounded sum/loop has a cost bound. Width, sign convention, bit order, truncation, and zero extension must be explicit; prototype bits are little endian on nonnegative integers. Dynamic divisions by zero and uncontrolled powers are rejected.

For each field $f\in\{\alpha,w,\tau,v,d,e,\beta\}$, allow

$$f(z)=f_0(z)+\sum_{q=1}^{p_f}\theta_{f,q}\,\phi_{f,q}(z).\tag{A}$$

The features $f_0,\phi$ are public index programs. The parameters are shared between sizes; optionally parameters are tied between fields as well. Gate-dependent signs can arise from features, negative learned coefficients, or index conditionals. Address magnitudes can vary with $i,t,u,r$ and need not factor into one magnitude times a mask.

Allow a finite decision tree whose leaves are expressions (A), with predicates depending on public indices. This is still linear in the numerical holes. Selecting a predicate or feature from a finite grammar can either happen outside the arithmetic learner or use Boolean selector conditionals. A test involving an unconstrained learned real parameter, and numerical-hole products, are excluded from the base language.

All seven fields need their own legal coordinate scopes: $\alpha$ sees $c$, $w$ sees $i,t$, $\tau,v$ see gate indices but no coordinate, $d$ sees $c$, $e$ sees $i,t$, and $\beta$ sees sizes. In particular the top direct address weights are not forcibly block-symmetric.

### 3.2 Useful feature families, including genuinely different architectures

- **Boolean index relations:** $[c=u]$, $[c=u\oplus v]$, $[i\in\operatorname{bits}(u)]$, indexed bit tests, Gray-code order, popcount classes, carry tests, interval membership, and modular classes. These provide literal table gates and asymmetric branching without enumerating a table of coefficients.
- **Walsh and mixed masks:** $(-1)^{\operatorname{popcount}(u\mathbin{\&}c)}$, and $(-1)^{\langle q(u,i,r),\operatorname{bits}(t)\rangle}$. A small Boolean index circuit generates $q$; do not allocate an unrelated unknown $q_{j,i}$ at every size. This is binary inner product, needing no finite-field machinery. If field multiplication is used, specify a uniform field representation/irreducible-polynomial algorithm.
- **Positional and hierarchical features:** $2^i$, $(m+1)^i$, $2^t$, $2^{im+t}$, $B^{\lfloor t/h\rfloor}$, piecewise powers on intervals, and sums of a few such profiles. These immediately admit more than one magnitude and can escape the equal-magnitude obstruction. Their output bit lengths are charged below.
- **Coupled table rows:** sums of several index characters, character times a public label predicate, nonlinear permutations of label indices, and row-local threshold-code coefficients. For example $\alpha_{u,r,c}=\theta_1\chi_u(c)+\theta_2\chi_{u\oplus e_0}(c)+\theta_3[c=u]$ shares parameters but need not be a scalar decoder of one Walsh coordinate. Index permutations merely permute raw table coefficients; no circuit input is being transformed for free.
- **Gate-specific address profiles:** $w_{u,r,i,t}$ may depend jointly on $u,r,i,t$, rather than one common scalar address query per channel. This is the intended route around the few-periodic-views obstruction, although it is not evidence that a small correct circuit exists.

For illustration, a legal raw gate can have

$$\alpha_{u,r,c}=\theta_1(-1)^{u\cdot c}+\theta_2[c=u],$$

$$w_{u,r,i,t}=2^i(-1)^{\operatorname{parity}((u\oplus r)\mathbin{\&}t)}
\left(\theta_3+\theta_4[t<\lfloor m/2\rfloor]\right)
+\theta_5[t=r][i=0],$$

$$\tau_{u,r}=\theta_6r+\theta_7N+\theta_8.$$

Products here are between public features and one learned scalar. This is not a proved Andreev construction. It illustrates mixed signs, two magnitude regimes, an asymmetric local perturbation, and a nonliteral table form using eight parameters shared over $Nm$ gates. A top rule and all direct terms must still be supplied and certified.

### 3.3 Raw compilation example with a known identity

The archived $m=2$ rank construction is represented with one type and $j=c'\in[0,N)$:

$$\alpha(j,c)=[c=j],\quad w(j,i,0)=2^i,\quad
w(j,i,1)=2^i(2\operatorname{bit}(j,i)-1),\quad \tau(j)=j+1.$$

Choose $v(j)=1$, $d(c)=0$, $e(i,0)=-2^i$, $e(i,1)=0$, and $\beta=-1$. At $k=2,j=1$ the emitted gate is exactly

$$[x_1+a_{0,0}+a_{0,1}+2a_{1,0}-2a_{1,1}\ge2].$$

It has no hidden rank input. The all-$k$, $m=2$ identity $\sum_jg_j=\sum_i2^ia_{i,0}+x_b$ proves correctness. The prototype regenerates this rule and verifies all raw inputs for $k=1,2,3$. Its intentionally incorrect $m=3$ extension produces a counterexample. The paired-column extension is representable too, but $S=N^{\lceil m/2\rceil}$ disqualifies it at balance.

This example is useful because a polynomial-only, equal-magnitude, or block-coherent grammar would miss it. It is not a reason to prefer its expensive generalization.

## 4. Language B: additive atoms with raw-gate contracts

The program is a direct affine score plus a finite union of indexed atom families:

$$F=\beta+d\cdot x+e\cdot a+\sum_{h<T}\sum_{r\in J_h(k,m)}\lambda_{h,r}\,A_{h,r}(x,a).\tag{B}$$

Atom coefficients, index sets, and $\lambda$ use Language A's index generators. Each atom returns a list of raw gates and top coefficients, possibly a direct affine correction. Addition concatenates lists; scaling changes top coefficients. **There is no operation feeding an atom's output to another bottom gate, and no multiplication of two compiled outputs.** Identical raw gates may be merged afterwards with exact arithmetic. Every count first uses the unmerged expansion.

Include the following atoms.

### 4.1 Raw ridge atom

$A=[\alpha\cdot x+w\cdot a\ge\tau]$, cost one. This escape hatch prevents the contract language from silently requiring literal-table gates, monochromatic slices, exact cancellation, or character separability. With enough ridge types it contains Language A, though its proof advantages diminish.

### 4.2 Row-dependent threshold-code slice

Let $L_r(x)=b_r+\sum_c a_{r,c}x_c$ have integer coefficients. Set $\ell_r=2L_r+1$, hence $\ell_r$ never vanishes on a Boolean table. Let $Z_r=d_r+\sum w_{r,i,t}a_{i,t}$ be integer-valued. For an integer $M_r>\max_x|\ell_r(x)|$ compile

$$g_r^+=\left[2M_r\sum w_{r,i,t}a_{i,t}+\sum_c2a_{r,c}x_c
\ge-2M_rd_r-(2b_r+1)\right],$$

$$g_r^-=\left[2M_r\sum w_{r,i,t}a_{i,t}-\sum_c2a_{r,c}x_c
\ge-2M_rd_r+(2b_r+1)\right].$$

Then

$$g_r^+-g_r^-=\operatorname{sgn}(\ell_r(x))[Z_r(a)=0].\tag{S}$$

The proof checks $Z\le-1$, $Z=0$, $Z\ge1$. These are two raw LTFs, with top weights $\lambda_r,-\lambda_r$. Multiple table bits may occur in every row. No global address query, scalar Walsh amplitude, or one-table-bit dominance condition is imposed.

Example: $\ell=1+2x_0-4x_1$, $Z=a_{0,0}-2a_{0,1}+3a_{1,0}-1$, $M=8$. The two gates are

$$[2x_0-4x_1+16a_{0,0}-32a_{0,1}+48a_{1,0}\ge15],$$

$$[-2x_0+4x_1+16a_{0,0}-32a_{0,1}+48a_{1,0}\ge17].$$

Their difference is the specified signed table code precisely on $Z=0$. This example is a compiler contract, not an Andreev circuit.

A candidate slice domain is $(h,u,r)$ with $h<T$, $u<N$, $r<m$, giving $R=TNm$, $S=2TNm$ before extra atoms. At balance constant $T$ would give $O(n^2/\log n)$; $T=O(\log k)$ would give $O(n^2\log\log n/\log n)$. **The required all-table/all-address decoding inequality is unknown**, even for these budgets. Letting $T=\Theta(k)$ loses the saving. Repeating a row for all possible address levels can do exactly that; count the levels, not only the row types.

During integer synthesis, avoid learning $M_r$ jointly with $w_r$. If the coefficient holes in $L$ have bound $K$, a public bound on $|\ell|$ supplies one fixed $M(k,m)$ valid for the entire search box. Then $2Mw$ is linear in learned integer coefficients. After extracting a candidate, $M_r$ can optionally be recomputed and the compiler contract rechecked. If magnitudes are unbounded reals, this integer slice interface is deliberately unavailable until a concrete rational row is cleared to integers. Such clearing is a compilation step, not a WLOG transformation of the original bounded grammar.

### 4.3 Mixed localized window

For a mask $z$ on $M_0$ chosen raw address coordinates, define the affine form

$$L_z=|z|+\sum_q(1-2z_q)a_q.$$

For an integer raw-table form $h$, cutoff $v$, and public integer $B>\max_x|h(x)-v|$, the atom

$$(-1)^{\sum_q a_q}(2[h\ge v]-1)[p\le L_z\le u]$$

expands as

$$(-1)^{|z|}\left(2\sum_{\ell=p}^u(-1)^\ell[BL_z+h\ge B\ell+v]
-(-1)^p[L_z\ge p]-(-1)^u[L_z\ge u+1]\right).\tag{W}$$

Cost is $u-p+3$, including two endpoints. This exact identity comes from the archived localized-window report. It uses no intermediate parity or code input. Signs, masks, widths, selected coordinate sets, and table forms can vary by row. For the character interpretation, selected coordinates must be whole blocks; the raw identity itself holds for any chosen subset.

Use these atoms for pooling and tail-cancellation hypotheses, not a mandatory independent product for each character. The single-middle-layer obstruction applies only to its exact constant-coverage subproblem. Varying windows escape that theorem but have not supplied economical coverage. If every character still gets its own full ladder, reject the proposed asymptotic accounting even when the compiler is short.

### 4.4 Rank and finite-difference contracts as auxiliary alternatives

The exact rank query $\sum_{r=0}^D[T(a)+x_{r\bmod Q}\ge r+1]-T(a)=x_{T(a)\bmod Q}$ has cost $D+1$. Its typed interface requires a valid integer affine $T\in[0,D]$ and a proof that the retrieved label is appropriate. It does not grant free block parities. Do not use $T=\sum_i2^is_i$ as a parity encoding: carries break it.

More generally a univariate finite integer sequence $f$ gives

$$f(L)=f(L_{\min})+\sum_{r=L_{\min}+1}^{L_{\max}}(f(r)-f(r-1))[L\ge r].$$

This is useful for discovering telescoping identities and merging thresholds. It costs the number of nonzero increments, potentially the entire range. If $L$ is affine in raw inputs it compiles legitimately; if $L$ contains a threshold output, code bit, or input product it does not.

## 5. Parameterized hierarchy and genuinely different portfolio members

### 5.1 A nested hierarchy inside each language

Use a **vector** of resource bounds, rather than one scalar “difficulty”:

- $T$: gate/atom types;
- $H$: index AST/DAG nodes, with shared subexpressions charged once;
- $p$: numerical holes across all fields;
- $d$: index decision depth;
- $b$: allowed index-bit inspection complexity;
- $\iota$: number of different index groups in one feature (e.g. $j,i,t$ interactions);
- $R$: sum-of-separable-features width, if this optional restriction is enabled;
- $\ell$: locality/support-description complexity, not an assumed raw support cardinality unless separately bounded;
- $G$: number of magnitude profiles/scales;
- $B_\theta$: learned numerator/denominator or integer bit budget;
- $\mathcal J$: allowed gate-domain schemes, with explicit counts;
- $E$: allowed finite exceptions, initially zero;
- $B_{\rm out}(k,m)$: coefficient-output bit bound.

Define a class by **at most** these resources. Pad with unused nodes/types, zero coefficients, or duplicate leaves; take unions of the allowed scale and domain menus. Coordinatewise increases then give actual set inclusion. Replacing a unit-magnitude menu with a positional-only menu is not a nested enlargement; it is another portfolio member. Likewise changing $S$ from $Nm$ to a completely different domain is not automatically nested unless zero-weight padding embeds the old one.

An index-bit bound must be a uniform syntactic rule, not “the first $b$ bits at the largest training size.” For example fixed-width tests, indexed `bit(j,i)`, a bounded-depth Boolean circuit on indexed bits, and a streaming automaton over all bits are different capabilities. Count each explicitly. A program consulting only low bits may create periodic masks and duplicate signatures; diagnose that rather than quietly giving it one new free mask bit per size.

Genuinely useful expressiveness milestones are: varying signs within blocks; eliminating common-reorientation coherence; introducing two magnitude classes; introducing positional profiles; coupling two table-row features; allowing $r$ to change an address direction as well as its threshold; allowing joint $u,i,t$ dependence; adding variable-width windows or free ridge exceptions; and finally introducing stateful index generation. None is claimed necessary for every logarithmic saving. Coherent lower bounds still allow logarithmic savings.

### 5.2 Portfolio alternatives

**Decision-list / index Boolean circuit rules.** These describe sparse exceptions, gates indexed by label conditions, mixed masks and local perturbations much better than low-degree arithmetic. Unknown selectors are finite Boolean choices; fixed-skeleton numerical learning remains linear. Switch here when failures are concentrated on named index relations, carry patterns, or exceptional label sets. Cap size-specific predicates to avoid interpolation masquerading as generalization.

**Finite-state or recursive index transducers.** Read the padded/interleaved bits of $(j,c)$ or $(j,i,t)$, with explicit termination and size conventions. A $q$-state deterministic transducer with alphabet size $a$ has $qa$ transitions and $qa$ output labels, rather than an independent coefficient for every pair. It can implement automatic sign sequences, carry-aware rules, and recursively repeated masks. With an output alphabet of $d$ digits, structural encoding needs $O(qa(\log q+\log d))$ bits. A terminal output can select one of $G$ predeclared magnitude profiles; alternatively emit $B$ coefficient digits in $B$ steps, charging $B$ time/bits. Fixed transitions make coefficients public constants in the learner. Symbolic transitions require $O(SnLqa)$ naive transition-selection constraints over index words of length $L$, before training examples; shared evaluation DAGs can reduce this. Do not mistake the exponentially many possible machines for a cheap search merely because $q$ is small.

Switch to transducers if the desired rule has a plausible recursion in $k$ or in address position, but an AST grows on every holdout size. Automata can encode parity of index bits with two states; arbitrary low-degree polynomial templates cannot do that comparably. Conversely a small automaton does not conveniently express every arithmetic relation or irregular finite index table.

**Tensor/low-rank coefficient rules.** Examples are $\alpha_{j,c}=\sum_{r<R}U_r(j)V_r(c)$ and $w_{j,i,t}=\sum_{r<R}A_r(j)B_r(i)C_r(t)$. With raw learned arrays, the first has $R(S+N)$ unknowns and the second $R(S+k+m)$, which still grow with the size and do not themselves constitute a uniform rule. With generated factors, replace array lengths by their feature-hole counts, but products of two unknown factors are bilinear, and three are cubic. Joint learning is QF_NRA or bounded finite-domain multiplication, not LRA. Fix one side, choose factors from finite menus, or do alternating fits as a heuristic with no completeness claim. Switch here only when coefficient matrices from independently verified witnesses exhibit reusable structure. Low matrix rank is a deliberate restriction; it is not equivalent to small circuit size.

**Sparse dictionary plus top fitting.** Fix a large pool of raw gates generated by several rule families, then learn only shared top/direct coefficients and optional supports. Fixed-support feasibility on samples is LP/LRA. Support selection is MILP/Boolean LRA. This is an excellent compiler calibration and identity-discovery stage, but it can never leave the chosen dictionary. In particular a huge pool need not fit the final gate budget, and the top rule must itself be shared across sizes rather than storing arbitrary $v_j$ at each size.

**Proof-directed additive identities.** Language B can learn cancellations between atoms, costs of windows, and positive versus exact-sum margins. It is more restrictive semantically but better aligned with an all-size proof than a raw AST. Switch from it to A when atom interfaces force a known blocked incidence or separable decoding problem. Switch from A to B after a raw candidate suggests a telescoping/rank/cancellation invariant worth proving.

There is no defensible total ordering of these languages by solver hardness or expressive efficiency. The portfolio should share counterexamples, not force the same architecture on every search.

## 6. Solver encoding, actual unknown counts, and bit costs

### 6.1 Unrestricted baseline and parameter savings

At one size a free raw model has

$$P_{\rm free}=S(n+1)+S+n+1=S(n+2)+n+1$$

real parameters. This includes bottom thresholds, top weights, all raw top weights, and the top threshold. Restricting the table generator does not change this count.

For $T$ types with $p_\alpha,p_w,p_\tau,p_v$ holes each and shared direct-rule sizes $p_d,p_e,p_\beta$,

$$P=T(p_\alpha+p_w+p_\tau+p_v)+p_d+p_e+p_\beta.$$

This is independent of $S,k,m$ for fixed syntax. If all fields have $q$ holes, $P=(4T+3)q$. Thus $T=2,q=2$ gives 22 holes; $T=4,q=8$ gives 152. At $n=32,S=128$, the free model has 4,385 holes, versus 152 in the larger example. At $n=8,S=3$, however, the free model has only 39 holes: a large grammar would increase difficulty. The small baseline must remain available.

For a slice family with $T$ types, $q$ holes in each of table coefficients, table bias, address coefficients, address offset, and top row weight, plus three direct fields, $P_B=(5T+3)q$. At $T=2,q=4$ this is 52 holes, but the integer slice restrictions and the induced Boolean gate patterns can still make synthesis hard. Numerical-hole counts do not predict wall time on their own.

If $H$ grammar slots choose from menus of size at most $K$, selectors need $O(H\log K)$ bits or $O(HK)$ one-hot variables/implications. Shared structural unknowns are not repeated per size. A fully symbolic AST has additional opcode/child selectors and acyclicity/type constraints, roughly $O(H\log H)$ structural bits for a fixed finite opcode set, but a potentially much larger evaluator circuit. Start with a small skeleton menu rather than that evaluator.

### 6.2 CEGIS learner on concrete examples

For sample $e=(x^e,a^e)$ and bottom gate $j$, introduce a Boolean $z_{e,j}$ with

$$z_{e,j}\ \longleftrightarrow\ L_{e,j}(\theta)\ge0.$$

With fixed index features, $L_{e,j}$ is affine in $\theta$. The top expression is

$$F_e=\beta+d\cdot x^e+e\cdot a^e+\sum_j\operatorname{ite}(z_{e,j},v_j,0).$$

Require $F_e\ge0$ for target 1 and $F_e<0$ for target 0. This is QF_LRA with Booleans/ITE. The apparent $v_jz_{e,j}$ is **not** an unknown-real product: implement it by ITE or implications. The bottom false branch is strictly negative, not $\le0$. This handles ties exactly.

For $E$ samples, there are $ES$ gate Booleans, $ES$ bottom comparisons/equivalences, and $E$ top comparisons. There is no polynomial-time guarantee: the activation choices already provide severe combinatorial hardness.

Naively, evaluating features and aggregating each raw sample costs $O(ESnp)$ arithmetic operations times feature-evaluation cost. With fixed structure, cache the design coefficients

$$A_{e,j,q}=\sum_c\phi_{\alpha,q}(j,c)x_c^e+
\sum_{i,t}\phi_{w,q}(j,i,t)a_{i,t}^e-\phi_{\tau,q}(j).$$

Then each bottom expression uses only the relevant $p$ holes, with formula size $O(ESp)$ plus top/direct expressions and $ES$ conditionals. Feature sharing, sparse rows, and repeated public direction patterns improve preprocessing, not its worst-case bound. Learned feature selectors instead require design coefficients for each menu entry or an evaluator DAG; do not quote the fixed-feature size for an unconstrained grammar.

With $d$ training sizes, $E_s$ samples and $S_s$ gates each, the numerical unknown count stays $P$, whereas gate Booleans become $\sum_sE_sS_s$ and preprocessing is $O(\sum_s E_sS_sn_sp)$ in the simple dense implementation. If every size gets 256 examples, gate budgets 4, 48, 96, 128 produce 70,656 activation Booleans. This is a realistic warning: sharing 152 reals does not turn the learner into a tiny LP. Once activation patterns are fixed, the residual arithmetic problem is linear.

### 6.3 Which operations leave the tractable core

- Finite known index products, remainder, powers and comparisons are evaluated outside SMT. They add coefficient bit size/time, not NRA.
- Learned integer magnitudes with fixed features give QF_LIA. Mixed integer bottom and real top parameters give QF_LIRA. Bounded integer coefficients allow PB/BV encodings.
- Boolean-selected affine coefficient branches remain Boolean LRA. A finite multiplication $\theta\cdot s$ with $s$ from a known finite menu can be expanded to ITE. The menu cost must be charged.
- Learned real $U,V$ in $UV$, learned matrix factors, or a variable $M$ multiplying variable $w$ give NRA. A learned base $B$ in $B^i$ gives degree-$i$ polynomial constraints at a fixed size, with growing degree. It is not a constant-cost exponentiation primitive.
- Integer variable divisors/remainders and unbounded integer products leave ordinary linear integer arithmetic. Enumerate divisors/bases externally or admit the harder fragment explicitly.
- Fixed-width bit-vector arithmetic wraps. It is sound only with a proof of sufficient width or an intentional modular index interpretation. Signed threshold sums require sign extension and overflow bounds; modular sums cannot silently replace integer LTFs.
- A full simultaneous $\exists\theta\forall x,a$ encoding is quantified and loses the concrete-example linear simplification. Keep synthesis and verification separate.

### 6.4 Margins and rational extraction

Do **not** impose independent unit margins per gate as a generic WLOG step. A shared grammar need not be closed under independent positive rescaling or threshold shifts. For example, constraints $\theta-1\ge0$ and $\theta-3/2<0$ are feasible, but replacing the latter by $\theta-3/2\le-1$ is infeasible. The constants may be fixed by the rule; a shared parameter cannot independently rescale them.

Strict inequalities are supported by exact LRA. Keep them, or impose an explicit optional margin condition and label the searched subclass. For genuinely integer-valued expressions, false means $\le-1$ automatically; this is a property of that integer language. A rational candidate can be scaled during standalone verification without claiming it remains in the learner's original bounded parameter box. Top-margin normalization also needs closure of the top rule under the required transformation; it is not automatically valid because the unrestricted circuit model permits it.

After a SAT learner response, serialize exact rationals, evaluate every accumulated sample independently, and only then call the full checker. Floating rational reconstruction is allowed as proposal generation, never as a correctness certificate. Unbounded LRA can return rationals with large denominators; count their actual bits. A finite linear branch admits ordinary linear-system determinant bounds depending on its dimension and coefficient bits, but those are finite-instance bounds, not a uniform bound on one successful all-size parameter vector.

### 6.5 Fixed candidate checker

Fix every coefficient to an exact rational. Declare $N$ independent Boolean table inputs and $km$ raw Boolean address inputs. Define each gate by its raw linear inequality, build a parity/XOR and multiplexer expression **only for the specification**, and ask

$$\exists x,a:\ C(x,a)\ne x_{b(a)}.$$

The specification's parities/multiplexer are not counted as circuit gates. This miter has $n$ free Boolean inputs and $S$ defined threshold outputs, $O(Sn+N+km)$ weighted terms/logical nodes, and coefficient-bit factor $B$. It can be represented as QF_LRA with Boolean ITE, integer PB constraints after exact denominator clearing, or overflow-safe BV. The prototype emits QF_LRA SMT-LIB. A straightforward adder/comparator bit-blast has conservative size $O(Sn(B+\log n)+S(B+\log S)+N+km)$; optimized PB encodings may be smaller. No polynomial runtime claim follows.

At $n=32$, $N=16$ raw table bits is the right universal encoding. Do not replace it by a restricted table generator. Enumerating all tables and all raw addresses would have $2^{32}$ cases; a symbolic miter avoids constructing that enumeration, though it may still time out. The exact affine-in-table extrema shortcut used by special literal-table witnesses is valid only after proving that whole score's affine dependence. Arbitrary threshold-code slices are nonlinear in $x$, so that shortcut cannot be assumed.

### 6.6 Output bit complexity, description length and wires

Let index features have magnitude bit length $B_f(k,m)$ and a rational parameter have numerator/denominator bit length at most $B_\theta$. If up to $p$ unrelated rational denominators occur in one field, a safe denominator-clearing bound is

$$B=O(pB_\theta+B_f+\log(p+1)),$$

not just $B_\theta+B_f$. With a common declared denominator or integer holes the sharper additive bound applies. Slice compilation with table bits $B_x$ and address/offset bits $B_a$ gives $O(B_x+B_a+\log N)$ output bits using the conservative $M=1+|\beta|+\sum|\alpha_c|$.

Examples: $2^i$ needs $O(k)$ bits; $(m+1)^i$ needs $O(k\log(m+1))$; $2^{im+t}$ needs $O(km)$ bits and is expensive but still polynomial in $n$. A coefficient $2^{2^{km}}$ needs $2^{km}+1$ bits. Its short AST does not make its explicit rational representation cheap. Enforce an output bit budget separately from AST length and gate count; if enormous output is intentionally allowed, state that cost rather than excluding it on mathematical grounds.

A dense raw circuit has $O(Sn)$ possible input wires and $O(SnB)$ explicit bit description. With $S=O(Nm)$ at balance, dense wires can be $O(n^3/\log n)$, even if the gate bound improves. Program description length is roughly $O(H\log H+P B_\theta)$ plus fixed macros/menus; generator work must at least write its output, with feature evaluation and big-integer arithmetic charged. For a fixed AST evaluated coefficientwise, a conservative runtime is $O(Snp\,\mathrm{Eval}(H,B))$. Uniform output complexity should be given in terms of $k,m,S,B$, not merely “polynomial in $k$,” since there are already $N=2^k$ table coefficients per dense gate.

## 7. Compatibility with successes and blockers

The following is an architecture audit, not an assertion that the proposed languages evade all possible lower bounds.

**General $d''$ construction and fixed-$k=3$ ladders.** Language A can express their characteristic table rows, selected blocks, level loops, positional thresholds, affine/quadratic index top weights, and direct corrections. Language B's finite-difference and raw-ridge interfaces can expand them. Their known count and fixed-$k$ limitations remain: $d''$ is quadratic, and the $+20$ family still has slope $21/2$ at $k=3$. Reproducing them tests syntax/compilation, not the subquadratic target. The archive's free-affine-top corrections must remain available.

**Mixed $m=2$ rank success.** Expressed by the constant-size rule in §3.3, including varied signs within blocks and positional magnitudes. This is a stronger expressiveness test than merely generating random mixed masks. The naive paired extension is rejected by its explicit $N^{\lceil m/2\rceil}$ cost.

**Finite one-sided hyperplane successes.** Their base-three coefficients and mask generator fit the public-index grammar; their irregular finite orientation/top-weight certificates can be imported as fixed finite fixtures or encoded with charged lookup branches. Do not claim those certificate tables already have a useful small all-$k$ grammar. The raw-ridge atom is needed to retain the successful one-sided sign-margin relaxation. Requiring two gates per slice, exact cancellation, or positive top weights throughout would unnecessarily exclude the finite witnesses. The 256-bottom cover at $(4,4)$ and 32/36-bottom fixed-$k$ witnesses do not imply economical balanced covers.

**Monochromatic central-layer covers.** The known construction's bound becomes superpolynomial at balance. A generated mask family with the same proved counting argument does not change that fact. A novel deterministic cover would need an independently better cover/count theorem; do not turn failure of the current upper estimate into a universal lower theorem for all covers.

**Coherence and reorientation.** If each gate has one sign within each block, unrestricted magnitudes still leave the coherent lower bound $\Omega(n^2/\log^3n)$; block symmetry has $\Omega(n^2/\log^{5/2}n)$. These forbid fixed power improvements in those classes but allow some logarithmic savings. A single global raw-coordinate complement can disguise coherence and only permutes target table labels, so it does not evade that obstruction. For full support, compare each pair of gate sign rows: within a block their coordinatewise product must be constant for a common reorientation to exist. With zeros, use the signed bipartite consistency test in `rules.py`, not an incomplete pair test. This is an inexpensive architecture tag, **not** rejection of all coherent candidates. Apply an actual numerical/theorem count bound only in its valid regime.

**Equal-magnitude parity-fiber rank.** The pending-review theorem applies when every gate individually has one common absolute value among **all** its nonzero address coefficients, $m\ge2$. Compute $Q_j$, the fully supported blocks, and $\eta_{j,i}$, the product of signs within a fully supported block. At each degree $r$, the matrix

$$V_r(R,j)=\mathbf1[R\subseteq Q_j]\prod_{i\in R}\eta_{j,i},\qquad |R|=r,$$

must have rank $\binom kr$. Identical raw masks are not the relevant statistic: distinct masks can have the same signature, or proportional columns at a given degree. Use exact rational rank, optionally only $r=1,2,\lfloor k/2\rfloor$ initially. Matrix generation costs $O(S\binom kr\,k)$ straightforwardly; exact elimination is polynomial in these dimensions but can be substantial at large $k$. Use this as a theorem-gated diagnostic pending independent confirmation, not silently as an unquestioned solver axiom. Do not apply it to positional weights, two-magnitude gates, or an arbitrary hybrid by deleting the unrestricted gates. Two magnitudes already break rank one; one binary-place address direction has full threshold-shift span. This is why multiple magnitude profiles should be admitted early, not left behind a very large AST budget.

**Per-character ridge repair tradeoffs.** The archived `push_upper` analysis identifies table-range, address-range, garbage/override, and amplification costs inside its specified per-character, table-linear construction families. Its range and defect arguments explain why changing ridge slopes, moving the residue, or lexicographically stacking those same ridges did not improve the leading constant. They are not unrestricted lower bounds. A new language should permit leaving that score decomposition, and any proposed reuse of it must count all repair/amplification gates rather than only the shortened main ridge.

**Full independent Walsh ladders.** Exact sign representation must retain every nonempty character in the separable class; their full address ranges sum to $\Theta(kmN)$. Changing signs alone does not shrink those ranges. Language A permits gates whose table and address rows jointly mix characters; Language B permits pooling and a raw-ridge escape. Those are strict architectural relaxations, not established savings.

**Single-kernel window reconstruction.** The exponential middle-layer mask-support theorem applies to the stated translate/constant-coverage equation (and its specified table-only correction), not arbitrary sign margins, varying widths, or general raw gates. Known varying-width cancellation is a positive regression, but its cost is noncompetitive. Reject only a declared instance of the blocked exact reconstruction problem, not a whole mixed-mask grammar.

**Odd sign-only Walsh reconstruction at $k=4$.** Fixed unequal character weights and a free table intercept do not rescue that exact odd sign-only architecture. Multiple amplitude channels, asymmetric ties and nonseparable gates remain outside the theorem. The grammar includes those escapes but should not presume that any gives a cheap all-size decoder.

**New scalar-shrinker blockers from pass 2.** The supplied follow-up report gives explicit scalable failures for $H\phi(Hy)$ with hard clipping $B=o(N)$, fixed sublinear powers, and fixed logarithmic shrinkers, including affine raw-input repairs. Record these as blockers to those particular decoders. The seed has ten spectral values $-2$ and six $+6$; repeated and punctured versions create asymptotic violations. Adding more numerical accuracy to the same failed shrinker is not an expressiveness milestone. Arbitrary coupled table halfspaces, mixtures of non-equivalent table bases, row-dependent address interactions, and size-dependent maps outside the proved cases are not ruled out. Affine permutations of the same decoder do not provide a new basis escape; same-control nonlinear shears have the supplied common-fixed-slice obstruction. A portfolio trying label permutations should expose control-coordinate diversity explicitly and retain the common-slice adversary. No positive decoding theorem for that alternative is known.

**Few periodic positional rank views.** If the entire top score is a sum of $L$ periodic code queries in the specified signed/permuted positional forms, with arbitrary codes/direct terms, the duplicate-sign-signature theorem rules it out when $k\ge2$ and $m-1>2^L$. At balance $L=o(k)$ fails. This is a structural filter on a precisely recognized contract, not a rule that every program needs $\Omega(k)$ masks. Row-dependent hyperplanes generally do not factor through those periodic queries. Check factorization explicitly before invoking the theorem.

**Literal table dictionaries.** The documented strict diagonal-dominance condition belongs to the one-table-bit gated representation being used there. Apply its exact score inequalities only after deriving that representation, with the correct offset conditions. Do not impose diagonal dominance on arbitrary multi-table-bit rows: threshold codes may rely on cancellation between nonliteral table functions. The generic raw checker needs no such assumption.

**Other lower-bound cautions.** High-survival random mixed signs block a particular uniform per-gate survival strategy; they are not a forbidden circuit class or a reason to reject a construction. The smoothness $O(V/m)$ claim is false and is not a language prior. The pending VC/Rademacher extension changes the advantage range, not the unrestricted worst-case exponent. Approximation, including the archived $O(n^{3/2})$ constant-error improvement, supplies no all-tail exactness certificate.

Every UNSAT record must name the gate domain, syntax bound, numerical domain, magnitude/output bound, normalization constraints, training sizes, and any enabled structural filters. Learner UNSAT on concrete examples excludes that declared grammar at those sizes, if exact and sound. Checker UNSAT verifies one fixed circuit at one size. Neither is an unrestricted circuit lower bound. UNKNOWN is neither outcome.

## 8. Implementable staged experiment

### 8.1 Infrastructure first

Use a record with: grammar version/hash; skeleton and index-bit conventions; parameters as rational strings; all gate-domain bounds and unmerged counts; generated raw coefficients; wire and bit counts; training/holdout size lists; normalization rules; solver/version/seed; exact status; counterexamples; and proof status. Store counterexamples as raw table bitstrings and raw address bitstrings. Deduplicate whole assignments, not generator descriptions.

Keep four independent components:

1. Public-index evaluator and typed raw compiler; deterministic output with exact integer/rational arithmetic.
2. Learner using only concrete input examples and shared holes/structure.
3. Arbitrary-table fixed-candidate miter, with exact raw evaluation of every SAT counterexample.
4. Cost/proof auditor that expands every atom and checks the claimed asymptotic gate-domain formula separately from finite correctness.

The included `rules.py` implements a small subset of (1), exact evaluation, two atom compilers, a coherence diagnostic, and SMT-LIB generation for (3). It does not implement the grammar search, CEGIS learner, full syntax validator, automata, rank filter, or an all-size proof engine. It is an intentionally small executable specification, not a claimed completed synthesis system.

### 8.2 Calibration and corpus

- **$n=8$, $(k,m)=(2,2)$:** retain the supplied unrestricted three-bottom baseline and two-bottom UNSAT as regression references. The local prototype checks the four-bottom rank rule instead; it does not re-prove optimality. A free model here has only 39 reals, so do not expect a 152-hole grammar to help. The earlier approximately 61.7-second S3 SAT is a historical single-run observation, not a performance promise.
- **$n=17$, $(3,3)$:** import the 32-bottom one-sided witness and the fixed-$k$ all-$m$ ladder rule as separate compiler fixtures. The all-table domain has $2^{17}=131072$ inputs; exhaustive verification is feasible for fixed fixtures.
- **$n=28$, $(4,3)$:** use symbolic raw tables from the start. This size tests width and odd-$m$ behavior without changing $k$ from the larger target.
- **$n=32$, $(4,4)$:** import the exactly verified 256-bottom fixture. Its special affine-in-table verifier is a fixture-specific cross-check. Generic candidates use 16 independent symbolic table bits, 16 raw address bits, and the full miter.

The known finite optima/records are calibration, not optimization objectives. Do not spend this task chasing S3 at $n=8$ or another isolated finite record. The previous short free searches at $n=17/28$ and the generator-family runs do not amount to an hours-long unrestricted $n=32$ search, and their UNKNOWN results give no architectural impossibility claim.

### 8.3 Search stages and budgets

**Stage A — fixed public feature skeletons.** Start with one or two types, 2–4 holes per field, exact LRA, and no learned arithmetic products. Use separately enumerated domain choices such as $S=CNm$ with fixed $C\in\{1,2,4\}$, or $R=CNm$ slices with their actual factor two. Each is one rule across the training sizes. Keep constant finite gate lists only for regression. Include sparse delta table rows, two-feature coupled rows, index-bit masks, positional/two-scale address features, and unconstrained-sign top/direct holes. Do not start with sign-only Walsh reconstruction.

Initially train on $n=8,17$ together, then add $n=28$, then $n=32$ using the **same** parameter tuple. A separate tiny free learner at $n=8$ is a calibration control, not a component stitched into the family. Use a small balanced initial corpus (e.g. 64 points per size), then add batches of 8–16 independently verified counterexamples. Refit on all accumulated points; never drop older examples merely to obtain SAT. Share a candidate's counterexamples with every language that targets that size.

Illustrative bounded policy: 30–60 seconds per initial learner call, 30 seconds per fixed-candidate miter, and a hard 15-minute budget per skeleton; give a promising fixed candidate an explicit one-off longer checker budget rather than automatically restarting indefinitely. These are proposed engineering limits, not experiments run here. Save the last model and exact status on timeout. A syntax-preserving solver benchmark can justify longer calls; merely adding another opaque minute to an unchanged failed architecture cannot.

**Stage B — isolate which freedom matters.** Compare, at identical gate domains and examples: one versus two magnitude profiles; fixed direction per level versus row-dependent direction; delta table rows versus two-feature and dense code rows; one-sided ridges versus paired slices; fixed-width versus variable-width windows. Increase one grammar resource at a time. Remove a block only after its structural theorem applies or a declared finite grammar is exactly UNSAT. If low numeric-hole count still gives hard activation branching, hold bottom rules fixed and fit top rules to diagnose the bottleneck.

**Stage C — modest structural synthesis.** Add finite feature selectors/decision depth, keeping arithmetic affine. Cache the index-feature design matrix for each skeleton/size. Search a small portfolio of mask generators and positional bases externally. Avoid allocating an independent learned field element or permutation per gate; use a finite uniform index program instead. Try two or three coupled table features before low-rank NRA.

**Stage D — contracts or transducers.** If raw candidates show a repeated cancellation/rank pattern, extract a Language B atom and prove its raw identity before using it at new sizes. If patterns are recursively indexed but AST size keeps growing, test small transducers. If factorization is the only observed structure, use finite factor menus or alternating fits as proposal methods; retain full exact checking and label their incompleteness.

**Stop/escalate by mathematical failure, not just time.** A counterexample showing carries, missing character, repeated sign signatures, common fixed slice, or a duplicated scalar shrinker should trigger a change in architecture. More magnitude bits cannot fix a theorem that already allows arbitrary weights. A solver timeout with no such obstruction calls for profiling, smaller examples, fixed-bottom fitting, or a different encoding; it is not evidence that a mathematical extension is required.

### 8.4 Adversarial examples without restricting table independence

Initial concrete points should include constants and complements; single spikes/holes; every character table and complement; majority/multiplexer tables; the five-point $k=4$ pattern and its translations/modulations; repeated/punctured versions at larger $k$; and independent random tables with the selected bit flipped. A raw address corpus should include minimal parity representatives, extreme counts, alternating patterns, concentrated ones, addresses agreeing in block counts but differing in arrangement, and duplicate-sign pair activations appropriate to a candidate's masks.

These are samples, not the universal table domain. The checker always quantifies arbitrary independent table bits. Do not claim completeness of this finite adversarial suite. When a new mask rule changes, regenerate candidate-specific adversaries and still run the generic miter. For genuinely mixed signs, replacing raw addresses by block counts is unsound unless a full symmetry theorem is established for that candidate.

### 8.5 Holdouts and all-size validation

Hold out $(2,1)$, $(2,3)$, $(3,2)$, $(3,4)$, and $(4,2)$ initially. They test boundary/odd/even behavior, a second $m=2$ rank case, and a new width combination. Exhaustive checks can cover those with $n\le20$; use the miter above that. Training at fixed $k$ with several $m$ must not become the entire generalization test.

After freezing the rule, compile balanced $(5,6)$, $(6,10)$, and $(7,18)$, with $n=62,124,254$. Audit gate counts, bit lengths, support, mask/signature patterns, and explicitly generated adversarial inputs. Attempt fixed-candidate symbolic checks with declared bounded budgets; UNKNOWN remains open. Such tests detect overfitting but do not establish all-size correctness. If a holdout counterexample enters training, it is no longer a holdout; designate fresh sizes and record the change.

A candidate can be promoted from finite experiment to a family only after all of these obligations are discharged:

1. **Total, uniform generator:** every public index, denominator, bit width, branch and loop is defined on the claimed domain; numerical parameters are finitely represented and fixed.
2. **Raw depth-two expansion:** every atom compiles into raw LTFs, all top direct terms are explicit, and no code/parity/rank is supplied as a hidden input.
3. **Global correctness:** prove an identity or sign inequality for every raw table and address. A useful proof form is $F=(2x_b-1)K(x,a)+E(x,a)$ with $K>|E|$, or a direct finite-difference/rank/cancellation identity. The inequality needs a genuine all-size proof, not an empirical minimum margin.
4. **Asymptotic count:** sum all index ranges, code rows, levels, endpoints, repair atoms, and exceptional cases. Show $S/(N^2)\to0$ under the declared balance. For $S\le C Nm f(k)$ this requires $f(k)=o(k)$.
5. **Representation costs:** prove the coefficient bit and generator-time bounds; report wires independently. A tiny program emitting exponentially long integers is not a small explicit description.
6. **Boundary and extension cases:** handle odd/even $m$, tiny $k$, floor balance and threshold ties. A finite exceptional prefix can be treated separately with a finite specification, but cannot hide an infinite set of missing sizes.

The most plausible proof paths for Language B are a row-incidence/table-code decoding identity, a globally shared window-tail cancellation inequality, or a new rank-count identity with a raw affine correction. All remain open. Language A may reveal a different invariant; do not require its discovery to fit one of those three in advance.
